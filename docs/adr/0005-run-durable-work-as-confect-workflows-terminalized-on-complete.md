# Run Durable Work as Confect Workflows Terminalized on Complete

Multi-step or failure-prone work runs on `@convex-dev/workflow`. A public Confect mutation inserts a request row in `inProgress` and starts the workflow through a raw internal mutation; the workflow body is an Effect that calls journaled steps through `Workflows.makeConfectWorkflowRunner`, so every step keeps Confect's encoded arguments, decoded returns, and typed errors; and the component's `onComplete` handler terminalizes the row as `completed` or `failed`. Clients subscribe to the row, never to the workflow component, so progress is an ordinary reactive query.

A typed failure from a step reaches `onComplete` only as text, often wrapped in `Workflows/UnknownError` by the runner, so `Workflows.classifyWorkflowError` recovers the first tag the workflow's declared error union knows, and the row stores that tag for user-facing copy. The workflow definition, start, and completion handlers stay in a plain `<group>.ts` file registered with `FunctionSpec.convexInternalMutation`, because defining them inside Confect creates a self-referential codegen type cycle. `exampleWorkflows` is the reference implementation of this shape.
